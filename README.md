# Full-Stack Coding Test

## Overview
This test is made of four parts:

1. Backend - writing code
1. Frontend - writing code
1. Backend - reviewing code
1. Frontend - reviewing code

All four parts are to be done in your own time.

### Writing code
The two parts involving writing code each require you to complete a small task with an existing codebase. They must be done in order as task 2 uses the result of task 1.

### Reviewing code
The two parts involving reviewing code will be done in your own time, and then discussed in the interview. For each you will be presented with a pull request to review. You will need to create these yourself via GitHub from the `pr-backend` and `pr-frontend` branches, respectively. You can find the button to create pull requests from those branches on the "Branches" page. Please do not merge the pull requests after reviewing. The changes you will be reviewing will be made to the original codebases you used for the first two parts, so you should already be familiar with them. Please add comments at a relevant place to the code being referenced ([see here](https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/reviewing-changes-in-pull-requests/commenting-on-a-pull-request)).

## Notes
In the repo you will find two folders; backend and frontend. Each one contains everything you will need for that task, including a README.md file that contains the specific instructions for that task.

## General Instructions
1. Create a free [GitHub](https://github.com/signup) account
1. Fork the repo [here](https://github.com/rubyplaynetwork/full-stack-coding-test/fork) (ensure "Copy the main branch only" is **unticked**)
1. Give the interviewers [read access](https://docs.github.com/en/account-and-profile/setting-up-and-managing-your-personal-account-on-github/managing-access-to-your-personal-repositories/inviting-collaborators-to-a-personal-repository) to your repo (you'll find the addresses in the email)
1. Create a branch to make your changes on
1. Complete tasks 1 and 2 in order
1. Ensure your changes have been pushed to the remote repo on GitHub (not pushed or merged to the `main` branch)
1. Create the two pull requests for tasks 3 and 4
1. Review the changes in each of the two pull requests, and leave comments with your notes (let us know if need assistance creating the pull requests)
1. Email the interviewers to let them know you have completed all four tasks

## Final notes
If you run into any trouble, or have questions, do not hesitate to contact your interviewers.

We look forward to hearing from you.

Good luck
